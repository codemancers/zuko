---
title: MCP Server
description: Connect AI clients (Claude, Cursor, VS Code) to Zuko CRM data via the OAuth 2.1 MCP server.
---

Zuko exposes a [Model Context Protocol](https://modelcontextprotocol.io) (MCP) server so AI clients can read and write CRM data on behalf of a logged-in user. Authentication uses **OAuth 2.1** with RFC 9728 protected-resource metadata — clients discover auth endpoints automatically.

## Endpoint

```
POST {BACKEND_URL}/api/mcp
```

Only `POST` is accepted. `GET` and `DELETE` return `405` — the server is stateless with no sessions to manage.

## OAuth flow

1. Client hits `/api/mcp` without a token → receives `401` with `WWW-Authenticate` pointing to `/.well-known/oauth-protected-resource/api/mcp`
2. Client fetches protected-resource metadata → discovers the authorization server at `{BACKEND_URL}/auth`
3. Client fetches `/.well-known/oauth-authorization-server/auth` → gets authorize URL, token URL, JWKS URI, and supported scopes
4. User completes the authorization code flow and approves scopes on the consent screen
5. Client exchanges the code for a JWT access token (audience = `{BACKEND_URL}/api/mcp`)
6. Client sends `Authorization: Bearer <token>` on every MCP request

Tokens are JWTs verified locally against `{BACKEND_URL}/auth/jwks` — no round-trip to the auth server per request.

## Scopes

| Scope                | Grants                                            |
| -------------------- | ------------------------------------------------- |
| `organizations:read` | List organizations the user belongs to            |
| `tasks:read`         | List and retrieve tasks                           |
| `tasks:write`        | Create and update tasks                           |
| `deals:read`         | List and retrieve deals                           |
| `deals:write`        | Create and update deals                           |
| `companies:read`     | List and retrieve companies                       |
| `companies:write`    | Create and update companies                       |
| `contacts:read`      | List and retrieve contacts                        |
| `contacts:write`     | Create and update contacts                        |
| `icps:read`          | List and retrieve ICP profiles                    |
| `icps:write`         | Create, update, and delete ICP profiles           |
| `leads:read`         | List and retrieve leads                           |
| `leads:write`        | Create, update, delete, convert, and revert leads |
| `campaigns:read`     | List and retrieve campaigns                       |
| `campaigns:write`    | Create campaign records                           |

## Tools

### `list_organizations`

**Scope:** `organizations:read`

Returns the organizations the authorized user belongs to. Call this first when the user belongs to multiple organizations to get the correct `organizationId` for task tools.

**Input:** _(none)_

**Output:**

```json
[{ "id": 1, "name": "Acme", "slug": "acme", "role": "owner" }]
```

### `list_tasks`

**Scope:** `tasks:read`

Returns up to 50 tasks (most recently updated) across all organizations the user belongs to.

| Input            | Type                                               | Description                             |
| ---------------- | -------------------------------------------------- | --------------------------------------- |
| `status`         | `"TODO" \| "IN_PROGRESS" \| "DONE" \| "CANCELLED"` | Filter by status (optional)             |
| `organizationId` | `integer`                                          | Restrict to one organization (optional) |

---

Returns full task detail including owners, subtasks, and parent task.

| Input    | Type      | Description                |
| -------- | --------- | -------------------------- |

### `create_task`

**Scope:** `tasks:write`

### `update_company_summary`

**Scope:** `companies:write`

Replaces the company's free-form [Editor.js](https://editorjs.io) summary document. This is a **full replace** — call `get_company` first if you need to preserve existing content, since there's no partial/block-level edit yet (see note below).

Supported block types: `paragraph`, `header`, `list`, `checklist`, `quote`, `code`, `table`, `warning`, `delimiter`. Inline formatting (bold, italic, highlight, inline code) is embedded as HTML tags inside a block's `text` field — e.g. `"<b>bold</b>"`, `"<mark>highlighted</mark>"` — not as separate block types.

| Input       | Type      | Description                                                              |
| ----------- | --------- | ------------------------------------------------------------------------ |
| `companyId` | `integer` | ID of the company to update (required)                                   |
| `summary`   | `object`  | Full Editor.js document: `{ blocks: [...], time?, version? }` (required) |

```json
{
  "companyId": 42,
  "summary": {
    "blocks": [
      { "type": "header", "data": { "text": "Overview", "level": 2 } },
      {
        "type": "paragraph",
        "data": { "text": "Enterprise account, <mark>renewal due Q3</mark>." }
      }
    ]
  }
}
```

> **Note:** block-level operations (append/insert/update/delete a single block by id, without resending the whole document) are planned as a follow-up — full-replace is the only mode today, matching how the web UI's autosave already writes this field.

### `create_icp_profile`

**Scope:** `icps:write`

Creates an ICP profile. If the user belongs to exactly one organization, `organizationId` can be omitted.

| Input            | Type      | Description                                            |
| ---------------- | --------- | ------------------------------------------------------ |
| `name`           | `string`  | ICP profile name (required)                            |
| `organizationId` | `integer` | Target organization (optional if user has exactly one) |
| `filters`        | `object`  | Apollo-style filter object (optional) — see below      |

`filters` is a loose key/value object matching Apollo's search filters, e.g.:

```json
{
  "industries": ["saas"],
  "employeeRanges": ["50,200"],
  "revenueRange": { "min": 30000 },
  "locations": ["United States"],
  "technologiesAnyOf": ["salesforce"],
  "personTitles": ["VP of Sales", "CTO"],
  "personSeniorities": ["vp", "c_suite"],
  "keywords": "enterprise software CRM"
}
```

Omit any field that doesn't apply. See `IcpFiltersDto` in `apps/backend/src/app/icp/dto/icp.dto.ts` for the full set of supported keys.

## Connecting a client

### Claude Desktop

Add to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "zuko": {
      "type": "http",
      "url": "https://your-backend.example.com/api/mcp"
    }
  }
}
```

### Claude Code

```bash
claude mcp add --transport http zuko https://your-backend.example.com/api/mcp
```

### Cursor / VS Code

Add a remote MCP server pointing to `{BACKEND_URL}/api/mcp`. The client handles OAuth discovery and the login flow on first use.
